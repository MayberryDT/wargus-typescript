## Coordinator T3 capture protocol

Use only the T3 preview/in-app Browser on Halla. Inspect listeners, select an
unused port, record the exact server PID, and clean up only that PID. Each tab
must stay under 30 seconds.

For each profile, load a fresh URL:

```text
/?smoke=1&perfProfile=<profile-id>
```

The URL applies a fresh deterministic profile and begins a disposable warmup
capture. After 5 seconds:

```js
window.__WARGUS_TS_PERF_RESET__();
window.__WARGUS_TS_PERF_START__('<profile-id>');
```

`PERF_START` with the same URL-loaded ID deliberately preserves the warmed
world instead of rebuilding it; switching IDs rebuilds the exact profile. For
`command-18`, immediately run both the strict smoke action and real T3 input:

```js
window.__WARGUS_TS_PERF_ACTION__();
```

Require `issued`, `moveIssued`, and `attackMoveIssued` to be true. After the
next rendered frame, require both `inputToCommand.sampleCount` and
`inputToNextRender.sampleCount` to be at least 2.

At capture +10 s save heap window 1 from `__WARGUS_TS_PERF_SUMMARY__()`. At
capture +15 s save the standard CPU/input summary. At capture +20 s call
`__WARGUS_TS_PERF_STOP__()` and save heap window 2. This is 25 seconds including
warmup. Write raw JSON outside Git under:

```text
/tmp/wargus-perf-018/<UTC-stamp>/<profile>-<width>x<height>.json
```

Do not commit generated JSON. Repeat `idle-25` in a fresh tab and compare
initial/profile IDs plus equal-window tick/entity state; timing distributions
may differ.

## Frozen budgets

- `army-100`: frame p95 ≤33.3 ms, p99 ≤50 ms, and `over50Ms/sampleCount` ≤1%.
- `command-18`: input-to-command p95 ≤50 ms and input-to-next-render-callback
  p95 ≤100 ms, with nonzero samples from both synthetic and real T3 input.
- Every profile: scheduler dropped delta = 0 and maximum backlog ≤0.25 s.
- Heap: used heap growth from the first to second equal 10 s window ≤15% when
  `performance.memory` is supported; otherwise record unsupported honestly.
