## Implementation

Logical checkpoints:

- `5ed8a3a` — add the numeric terrain metadata cache and exhaustive verifier.
- `73821db` — migrate the owned passability, forest, and opacity consumers.
- `177a41f` — complete raw normalization and opacity parity fixtures.

`src/simulation/terrainMetadata.ts` builds one internal numeric
`Map<number, number>` per tileset identity and retains it in a `WeakMap`.
Repeated lookups return numbers and do not expose the map, source arrays, or
`Set` instances. Duplicate slot entries preserve legacy first-match behavior.

The raw path uses the world consumer's legacy bitwise tile-to-slot rule.
The passability path separately preserves its nonnegative slot rule and returns
the land-only mask for removed-tree tile `126` before any cache lookup.

Diagnostics are plan-local and remain outside `WorldState`, saves, gameplay
decisions, and Plan 018 summaries:

- `plan019.terrainMetadata.cacheBuilds`
- `plan019.terrainMetadata.cacheHits`
- `plan019.terrainMetadata.slotLookups`

No occupancy, A* ordering, path selection, FOV geometry/cadence, save schema,
tile asset, renderer, `orders.ts`, or `renderWorld.ts` change is present.

## Residual risk

The cache contract depends on tileset objects being immutable after first use.
Repository consumers replace tileset identities rather than mutating their
`slots` or `flags`; the focused verifier proves that the cached numeric snapshot
cannot be changed through returned values. Browser/performance acceptance is
the only remaining plan gate.
