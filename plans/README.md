## Gameplay Design Constraints

- The fixed demo deliberately starts with exactly one selected Peasant and one enemy Peon, with no starting Hall.
- The high-resource start (`10,000 gold / 5,000 wood / 5,000 oil`) remains deliberate; harvesting supports sustained production rather than gating the first army.
- Mission objectives are not part of this roadmap.
- Playable browser behavior is the acceptance criterion. Typecheck/static verifiers protect regressions but do not substitute for the named play sessions in each plan.
- Do not add starting workers, starting buildings, starting armies, or hidden movement-only speed multipliers.

## Findings Considered And Rejected

- Full `orders.ts` rewrite: rejected for now. The file is too central to safely restructure in one pass; plan 006 starts with a small pilot extraction and leaves larger gameplay slices for later plans after the verification baseline is green.
- Replacing all source-fragment verifiers at once: rejected for now. Several static verifiers encode real source-port invariants; plan 005 fixes the known stale contract and sets boundaries for future conversions to behavior checks.
- Adding more starting workers or a starting Hall: rejected. The one-Peasant/no-Hall opening is a deliberate game premise; plan 017 shortens it with coherent global pace instead.
- Adding mission objectives as a completion mechanism: rejected. Objectives do not make the existing mechanics more playable and are outside this roadmap.
- Lowering the high-resource start during this pass: rejected. The current product direction favors reaching base-building and combat quickly; an economy-first redesign should be a separate decision.
- Keeping the hidden 1.3x movement multiplier: rejected. It distorts movement relative to construction, training, combat, and gathering; plan 017 replaces it with the highest-scoring honest global candidate from a frozen bakeoff.
- Rewriting `orders.ts` before repairing behavior: rejected. Plans 011-016 make surgical changes around existing seams; architectural extraction can follow once mechanics are stable.
